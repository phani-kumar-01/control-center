## 1. Executive Summary: Hardware & Firmware Identity

### 1.1 Why `Acer Aspire A715-79G` Is a Clevo ODM Board (Not Acer Predator/Nitro WMI)
Phase 1 hardware recon and Phase 2 firmware/app correlation independently establish that the **Acer Aspire 7 A715-79G** (`Product Name: Aspire A715-79G`, `Version: 1.14`, `BIOS: INSYDE Corp. 1.14RA1` dated `09/08/2025`, `BIOS Revision: 7.14`, `EC Firmware Revision: 7.13`, `Intel Core 5 210H`, `NVIDIA RTX 4050 Mobile [10de:28a1]`) uses a **Clevo ODM chassis/board** (NP50RNA / Clevo DCHU architecture) with **Insyde BIOS** and an **ITE `IT5570` (`0x5570`) Embedded Controller**, rather than Acer's native Predator/Nitro WMI interface:

1. **Zero Acer Predator/Nitro WMI GUIDs:** None of `acer-wmi`'s GUIDs (`AMW0_GUID1`: `67C3371D-...`, `AMW0_GUID2`: `431F16ED-...`, `WMID_GUID1`: `6AF4F258-...`, `WMID_GUID2`: `95764E09-...`, `WMID_GUID3`: `61EF69EA-...`, `WMID_GUID4`: `7A4DDFE7-5B5D-40B4-8595-4408E0CC7F56`, `WMID_GUID5`: `79772EC5-04B1-4bfd-843C-61E7F77B6CC9`, or `ACERWMID_EVENT_GUID`: `676AA15E-...`) exist under `/sys/bus/wmi/devices/`. Consequently, `acer_wmi` never autoloads or binds.
2. **Clevo ACPI & WMI Devices Present:** `/sys/devices/platform/` exposes unbound **`CLV0001:00`** (`MODALIAS=acpi:CLV0001:`) and **`CLV0002:00`** (`MODALIAS=acpi:CLV0002:`), and `/sys/bus/wmi/devices/` exposes the exact Clevo WMI triad on `PNP0C14:01` plus NVIDIA MXM WMI on `PNP0C14:00`:
   - `ABBC0F6B-8EA1-11D1-00A0-C90629100000` (`event`, `notify_id: D0`, `PNP0C14:01`)
   - `ABBC0F6C-8EA1-11D1-00A0-C90629100000` (`event`, `notify_id: D1`, `PNP0C14:01`)
   - `ABBC0F6D-8EA1-11D1-00A0-C90629100000` (`method`, `object_id: BB`, `PNP0C14:01`)
   - `F6CB5C3C-9CAE-4EBD-B577-931EA32A2CC0` (`method`, `object_id: MX`, `PNP0C14:00` — `mxm_wmi`)

5. **Why Fans Appeared "Off" at Boot / Light Load (Kernel Bugzilla `#222019` & Phase 1 EC Dump Cross-Check):**
   - **Linux Kernel Bugzilla `#222019`** (`https://bugzilla.kernel.org/show_bug.cgi?id=222019`, filed `2026-09-16`, Status: `NEW`, `"acer-wmi: no device matching for Acer Aspire A715-79G - EC automatic fan control inactive at boot"` on BIOS `1.07.01TACI`): documents that with no driver claiming `ABBC0F6B/C/D` (or `CLV0001`), the EC stays in its quiet default profile where fans remain off/very slow at `60–75 °C` unless `Fn+1` (Cooler Boost) or ACPI `SCMD(0x69, ...)` sets balanced mode (~1300 RPM idle, ramping under load).
   - **Phase 1 `recon/ec_dump_idle.hex` Verification:** Cross-checking our machine's read-only 256-byte EC dump against `the3rdchild/nixos-config`'s `A715-79G` EC register map (`acer_fanctl.c` & `reverse-engineering.md`) confirms **exact alignment**:
     - `0x07` (`TMP`): `0x31` = **49 °C** (exact match to `sensors.txt`: `acpitz_0-acpi-0: temp1 +49.0°C`).
     - `0xCE` (`DUT1`, CPU fan duty 0–255): `0x47` = `71/255` (**~28%**).
     - `0xCF` (`DUT2`, GPU fan duty 0–255): `0x47` = `71/255` (**~28%**).
     - `0xD0..0xD1` (`RPM1`, LE `u16` tach period): `0x03 0xd8` → `0xD803` (`55299`) → `60,000,000 / 55299` ≈ **1085 RPM**.
     - `0xD2..0xD3` (`RPM2`, LE `u16` tach period): `0x03 0xdb` → `0xDB03` (`56067`) → `60,000,000 / 56067` ≈ **1070 RPM**.
     - *Interpretation:* On our `BIOS 1.14RA1` / `EC 7.13`, both fans **are spinning quietly at ~1070–1085 RPM (~28% duty) at 49 °C idle**, which explains why the user did not hear them and why CPU Peak reached only `63.0 °C` (`acpitz` `64.0 °C`) during the 60s `stress-ng --cpu 12` test — though Linux currently has zero sysfs `hwmon`/`fan*_input`/`platform_profile`/`kbd_backlight` visibility or control.

## 3. Ranked Table of Candidate Approaches (`AGENT_WORKFLOW.md` §3.3)

### 3.1 Critical Firmware Fork Observed Across A715-79G Sources
Before selecting a driver, Phase 2 uncovered a **vital firmware detail** across verified A715-79G implementations:
- **Variant 1 — Clevo DCHU `_DSM` Path (`CLV0001` `_DSM` `93f224e4-fbdc-4bbf-add6-db71bdc0afad`):** Used by `tuxedo-drivers` (patched `Atul977` / `nick42d`), `opendchu`, `clevo-acpi-dkms`, `open-uniwill-cc`, `KeyLume`, `AspireSense`, and `Acer-Aspire-7-A715-79G-RGB`. ## 4. Recommended Safe Phase 3 Execution Plan (For Phase 2 Gate)

Following `AGENT_WORKFLOW.md` Sections 1, 4, and 9:

### Step 1 — Read-Only Firmware Interface Verification (Requires `sudo`, Zero Hardware Writes — Path D Observation First)
Before loading any out-of-tree kernel module or enabling any EC writes, run strictly read-only ACPI/WMI inspection on our exact **`BIOS 1.14RA1`** (`EC 7.13`):
1. **Dump & decompile ACPI tables** into `control-center/recon/acpi/` (using `acpica-tools`: `acpidump`, `acpixtract`, `iasl`):
   - Inspect `CLV0001._DSM` (`93f224e4-fbdc-4bbf-add6-db71bdc0afad`), `PNP0C14:01` (`WMBB` / `ABBC0F6D`), `SCMD`, `ECMD`, and `ECRAM` fields.
   - **Key binary question answered in 1 command:** Does `BIOS 1.14RA1` implement `_DSM 0x67` (RGB/brightness), `0x68`/`0x69` (fan duty/auto), `0x0C`/`0x79` (fan RPM/mode) — or did it stub/drop `0x67` in favor of `ECMD 0xCA` (`the3rdchild`/`J-525` style)? Also inspect whether `_OSI` gates any thermal/fan methods.
2. **Decode WMI Binary MOF (`bmfdec`):**
   - Check `/sys/bus/wmi/bmof/*` or `/sys/devices/platform/*/*:00/wmi_bus*/.../bmof` (if exposed) to read exact WMI method signatures for `ABBC0F6D`.
3. **Verify `thermald` & Path A baseline:**
   - Confirm `thermald` active configuration (`systemctl status thermald`) and note `platform_profile` remains absent. (Only test `acpi_osi=...` GRUB parameters if DSDT explicitly shows OS-string gating **and** the user approves a GRUB change per Safety Rule 9.)

### Step 2 — Driver Build & Controlled Hardware Verification (Requires Explicit User Approval per Safety Rule 9)
Only after Step 1 confirms the exact firmware interface and the **user approves building/loading an out-of-tree kernel module**:
1. **Install build headers if missing:** `linux-headers-$(uname -r)` and `build-essential` (`dkms` is already installed; `SecureBoot disabled` was confirmed in Phase 1).
2. **Path B — Build & test out-of-tree in `control-center/driver/` (not system-wide DKMS yet):**
   - **If DSDT confirms `CLV0001._DSM` (`0x67`/`0x68`/`0x69`/`0x79`/`0x0C`):** Test patched `tuxedo-drivers` (`clevo_acpi` + `tuxedo_keyboard` with `tuxedo_is_compatible() -> true`) **or** `opendchu` / minimal `CLV0001` driver (incorporating standard `hwmon`, single-zone RGB `0xF0` GRB + `0xF4` brightness, and a `clevo-acpi-dkms`-style 15s dead-man's-switch watchdog returning fans to `auto` on timeout/exit).
   - **If DSDT shows `SCMD 0x68/0x69` + `ECMD 0xCA` (and `_DSM 0x67` absent):** Adapt `the3rdchild`'s `acer_ec_core` / `acer_fanctl` / `acer_ec_kbd` approach in `control-center/driver/` using the DSDT-verified ACPI methods (`SCMD`/`ECMD`) rather than raw `ec_sys` writes.
   - **Verification order (safe-first):** Load via `sudo insmod`, check `dmesg` for clean `CLV0001` bind, test **read-only** temp/RPM/duty first, then test **keyboard LED** off/brightness/color (`0xF0` single-zone GRB or `0xCA`), then test **fan mode** (`auto` → moderate duty → `auto`) while logging live temperatures (must remain `< 80 °C` idle / `< 90 °C` load). Record all tests in `driver/TEST_LOG.md`.
3. **Path C Fallback (only if Path B write methods are missing/non-functional):**
   - Diff read-only `ec_sys` dumps across `Fn+1` (Cooler Boost) / AC states to confirm writable EC registers, then request explicit per-register user approval before enabling `ec_sys write_support=1` or configuring `nbfc-linux`.
4. **Phase 3 Gate Deliverable:**
   - Produce the per-feature support matrix (`keyboard brightness`, `keyboard color`, `fan mode`, `fan RPM readout`, `temperature readout`, `performance profile`, `battery limit`) marked `WORKS (path X)`, `READ-ONLY`, or `NOT POSSIBLE (reason)` before beginning Phase 4 implementation.
